What was requested, and why
========================================
I requested an on-demand ml.m5.large training quota of 2. Lab 4's pipeline needs one concurrent training job; 2 leaves room to start a second job while the first is still running. I did not ask for a larger number. The course dataset trains in under two minutes, each run costs roughly $0.10–$0.30, and an approved quota bills $0 until a job is actually launched. A request of 20 would be capacity this workload cannot defend. AWS later applied 20 anyway; the number I can justify is still 2. If that on-demand request had still been 0 when Lab 4 opens, the fallback was spot ml.m5.large. The published AWS default for spot is 4, but the value applied on this account was 0, so spot would have failed the same way until it was raised. Service Quotas will not accept a spot request of 2, because any request must be greater than the default of 4, so I requested 5 (case 179072804200950). That is one job plus overlap, which is the same reason as the on-demand request of 2; 5 is only the smallest integer the API allows. That case is now CASE_CLOSED and the applied spot quota is 10. A spot job can be interrupted, so that path would need checkpointing and retry. Interruption risk is low for a job under two minutes on 10,000 rows. It is not needed for Lab 4, because the on-demand quota is already 20.
